## Risultato applicativo

- Compilatori TS/Rust 0.2.0: sorgenti ammesse soltanto in `20_RAW_SOURCES/`, lettura dei byte una volta con accessi ancorati a directory aperte, rifiuto di symlink e file speciali. Hash e contenuto derivano dagli stessi byte. Le fonti non vengono scritte dal compilatore.
- Bozze in `90_PROPOSALS/`: identificatore della fonte derivato dal percorso completo rispettando il case, nome di revisione distinto, scrittura esclusiva in staging e pubblicazione senza overwrite. Una fonte modificata genera una nuova revisione; una fonte invariata viene saltata. Le bozze umane esistenti non vengono riscritte. Nessuna promozione automatica.
- Indice: lock esclusivo condiviso tra TS/Rust; lettura e validazione prima di scrivere; indice non valido produce errore senza azzeramento. Sostituzione atomica del file indice; rollback della nuova bozza se il salvataggio indice fallisce normalmente. Letture successive possono consumare l’indice dell’altro runtime.
- Provenienza: SHA-256 completo, percorso relativo, versione compilatore, ID fonte. `first_compiled_at` esprime la prima compilazione, senza inventare una data d’importazione. L’indice legacy migra esplicitamente il vecchio campo `imported_at` con questa semantica.
- HTML: estrazione di testo con lo stesso algoritmo TS/Rust; tag, eventi, risorse e contenuti script/style/iframe/object/template/noscript non vengono pubblicati come markup attivo. Il frontmatter Rust è serializzato con serde_yaml e validato; TS usa js-yaml e FrontmatterSchema.
- Batch: risultato per fonte, continuazione dopo errori di singoli file; UTF-8 invalido rifiutato e formati non supportati distinti dagli errori.
- Desktop: IPC lista proposte, elenco revisioni e anteprima del Markdown in testo mediante React, senza esecuzione HTML o caricamento di risorse. Refresh Sources disponibile nella scheda Sources; errori di batch per fonte visibili. Gli errori compiler non alterano falsamente il report d’integrità M3.

## Limiti dichiarati e riproduzione

- La pubblicazione dei singoli file è atomica; bozza e indice non costituiscono una transazione resistente a spegnimento o kill in ogni punto. Una terminazione forzata può lasciare lock/staging o una revisione non indicizzata; il lock non viene rubato automaticamente. Prima del recupero verificare assenza di compilatori attivi e consistenza di indice/bozze. I test verificano gli errori gestiti e la concorrenza cooperativa, non un guasto hardware.
- Le anteprime mostrano sorgente Markdown in testo, non HTML renderizzato. Nessuna AI in M4; approvazione resta M7.
- I nuovi file sono correttamente segnalati come aggiunti dalla verifica M3: M4 non riscrive il manifest d’integrità per mascherarli.
- macOS ARM64 verificato. Firma/notarizzazione/distribuzione restano M9.

Riproduzione: `pnpm test`, `pnpm typecheck`, `pnpm build`, poi `scripts/m4-native-check.sh` (configura Rust locale, esegue test/driver/parità M2/E2E M3-M4/build Tauri). Il flusso UI offline è documentato sopra e distinto dai test CLI. Baseline AG precedente conservata in `.local/m4-baseline/`.
